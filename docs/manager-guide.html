Slow Dough Pizza Co. — Content Manager Guide

Updating the menu, blog & dough announcement yourself
For the owner / manager
Version 1.0 · about 5 minutes
Where: open your-site/admin (or click the small “Staff” link at the very bottom of the website). Sign in with the GitHub account that was invited to the Slow Dough repository.

1Sign in

Click Login with GitHub; a small window opens — approve it once. If it says “not a collaborator with write access”, ask the site owner to invite your GitHub account.

2Pick what to change

Site Settings = Dough Announcement + Hours & Schedule · Daily Menu = one entry per category · Blog Posts. Click an entry to edit, or New … to add one.

3Edit — the right-hand side is a live preview in the site’s own look

Daily Menu: change a price, text or tags. Switch Available today off to show “Sold Out Today” without deleting the dish. Add menu items adds a dish, ✕ removes it, the ≡ handle reorders. Tags “Vegetarian” / “Vegan” get the green leaf.
Dough Announcement — the dark strip at the top of every page: headline, detail text, on/off switch, and an Alert style for sold-out nights or closures.
Blog Posts → New Blog Post: title, author, publish date, excerpt (shown on the card), key takeaways, and the essay in Body. Use the toolbar for headings, bold/italic, quotes, lists, links. Newest first.

4Save — nothing is live yet

Click Save. The change is stored as a Draft that only you and the reviewer can see. Keep editing and saving as often as you like.

5Send it for review

Open Status and choose In review, or Ready when it is final. The reviewer is notified.

6If something is refused

Plain text only. A red message under a field means the text contains something that looks like web code (e.g. <b>, <script>) or is too long. Remove it and save again — nothing is lost.

7Review & go live

The Workflow tab lists every pending change. Behind the scenes each one is a GitHub pull request on its own branch — never directly on the live site. A reviewer approves and merges it on GitHub; the website then rebuilds itself and the change is live in about 2 minutes. If you are also the reviewer, open the entry and click Publish → Publish now once it has been approved.

Good to know

StatusMeaning
DraftSaved, visible only in the admin. Keep editing freely.
In reviewWaiting for the reviewer to approve.
ReadyApproved / final — about to be published.
PublishedMerged; the site rebuilds and goes live in ~2 min.
  • Changed your mind? Open the entry from Workflow and click Delete unpublished entry.
  • Something live is wrong? Edit the entry again and save — the fix goes through the same quick review.
  • Not seeing it? Wait 2 minutes, then refresh the website (Ctrl/Cmd + Shift + R).
  • Prices are numbers only, e.g. 19 or 19.5. Dates use the calendar picker.
  • Can’t sign in? Your GitHub account needs Write access to the site repository — ask the site owner.
